# Beginner PHP Track Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (recommended) or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add eight beginner PHP lessons that execute real PHP.wasm code in the browser and render the generated HTML in the existing Web Learning Lab preview.

**Architecture:** PHP projects use an explicit `php-wasm` manifest with `index.php` as the entry. A cached `@php-wasm/web-8-4` loader and `@php-wasm/universal` runtime write the in-memory project files and execute the entry file; `usePreviewRuntime` turns the response into an iframe document and reuses the existing bridge, DOM signals, feedback, and progress flow. Existing HTML/CSS/JavaScript/React projects keep their current preview path.

**Tech Stack:** React 18, Vite 6, `@php-wasm/universal` 3.1.52, `@php-wasm/web-8-4` 3.1.52, existing local-storage project model, existing iframe bridge and declarative lesson validator.

**Spec:** `docs/superpowers/specs/2026-09-24-php-track-design.md`

## Global Constraints

- Use PHP minor version `8.4` for every PHP lesson.
- PHP runs in an in-memory WebAssembly runtime; do not require XAMPP, Docker, a local PHP installation, or a Node/PHP server.
- Do not add databases, MySQL, Composer, authentication, sessions, uploads, host filesystem mounts, or production deployment behavior.
- Keep the existing iframe boundary `sandbox="allow-scripts"`.
- Keep PHP output and request input deterministic and local to the current project.
- Preserve existing HTML/CSS/JavaScript/React project normalization and preview behavior.
- Use Polish visible lesson copy and task instructions.
- Do not add or run automated tests in this task unless the user separately requests test work; verify with `npm run build` and the browser flow described in Task 7.

## Review Focus

- **Late or overlapping PHP runs:** a slower WebAssembly response must not replace a newer run; pin this to the run-id check in `usePreviewRuntime` and the serialized queue in `phpRuntime.js`.
- **A stale virtual file:** a deleted or changed project file must not be inherited from the previous run; pin this to the per-run virtual root or explicit file cleanup in `phpRuntime.js`.
- **Full-document and fragment output:** both `<html>...</html>` and a plain PHP fragment must render once with one bridge; pin this to `buildPhpPreviewDocument`.
- **POST data and escaping:** the form lesson must pass deterministic form data and show escaped text; pin this to `phpRequest` execution and the lesson 607 recipe.
- **Fatal PHP errors/timeouts:** non-zero exit, stderr, loader failure, or timeout must surface in feedback and invalidate completion; pin this to the PHP result normalizer and preview error state.


Keep both packages at the same release so the universal API and browser loader

- [ ] **Step 2: Create the cached runtime service**

Implement `src/services/phpRuntime.js` with this boundary:

```js
import { PHP, PHPRequestHandler } from '@php-wasm/universal';
import { getPHPLoaderModule } from '@php-wasm/web-8-4';

export const PHP_VERSION = '8.4';
const ROOT = '/wll-php';

let runtimePromise = null;
let phpInstance = null;
let queue = Promise.resolve();

export function resetPhpRuntime() {
  phpInstance?.dispose?.();
  phpInstance = null;
  runtimePromise = null;
}

export function runPhpProject({ files, entry = 'index.php', request = {} }) {
  const job = queue.then(() => executePhpProject({ files, entry, request }));
  queue = job.catch(() => undefined);
  return job;
}
```

`executePhpProject` must lazily create `new PHP(await loadWebRuntime('8.4'))`,
create a unique root such as `/wll-php/run-${crypto.randomUUID()}`, write every
normalized project file below that root, and execute the entry in file mode with
`php.run({ scriptPath })` for the default request. Use `TextDecoder` or the
response's text accessor to normalize stdout to a string. Convert response
stderr/error collections and a non-zero exit code into `errors` without hiding
the raw strings. Return `requestKey: null` for a normal run.

For a request with `method`, `query`, or `form`, create a
`PHPRequestHandler` for the unique root and call its `request({ url, method,
body })`; encode the declared object as URL-encoded form data, set the matching
`Content-Type`, and return `requestKey` as a stable JSON string of the request
object. Never accept arbitrary URLs or host paths.

If loading or execution throws, call `resetPhpRuntime()`, return a result with
`html: ''`, `exitCode: 1`, and a readable error. Do not let a rejected queue
poison later jobs. Wrap each execution in a five-second timeout; on timeout,
reset the runtime and return `PHP nie odpowiedział w ciągu 5 sekund.` in
`errors`.

- [ ] **Step 2: Add the asynchronous PHP run path**

Implement a `runPhpPreview(nextFiles, documentPath, request, shouldCheck)`
callback inside `usePreviewRuntime`. It must:

1. clear old signals/errors and set `status: 'running'`;
2. increment the run token before awaiting PHP;
3. call `runPhpProject({ files: nextFiles.files, entry: documentPath, request })`;
4. ignore the result if its run token is no longer current;
5. set `previewDocument` from `buildPhpPreviewDocument` and bump `previewKey`;
6. set `signals.phpRequest` to `{ key: requestKey }` when a request was used;
7. collect iframe signals after `ready`, then evaluate checks exactly as the
   existing path does;
8. put loader/runtime errors in `runtimeState.errors`, set `status: 'error'`,
   and leave check results empty.

Keep `runPreview()` and `savePreview()` API names so `App.jsx` and the editor do
not need a separate PHP control. The PHP path may return a Promise; existing
button handlers can safely call it without awaiting.

- [ ] **Step 3: Run form checks through PHP, not iframe clicks**

- [ ] **Step 4: Add the validator case**

Add this branch to `evaluateOne`:

```js
case 'phpRequest': {
  const ran = signals.phpRequest?.key === JSON.stringify(check.request ?? {});
  const passed = ran && (signals.runtimeErrors || []).length === 0;
  return passed
    ? resultFor(check, true, 'PHP otrzymał dane żądania i wygenerował wynik.')
    : resultFor(check, false, 'Nie uruchomiono oczekiwanego żądania PHP.');
}
```

The output itself is checked by neighboring `textEquals`/`textContains` checks,
so `phpRequest` only asserts that the declared request was actually executed.
